## Three things that are wrong right now

1. **The chat shows one model where it should show two.** `GET /api/v2/models`
   intersects the caller's `/v1/models` with a superset built at boot using the
   *deployment* credential, so a user's own agent is in their per-caller list
   and not in the superset, and the intersection drops it. Reported by the user.
   The fix is to make the caller's catalogue the source rather than a filter,
   which also means the chat's `validModelIdSchema` can no longer be built from
   the superset alone.

2. **Where agents live is contradicted and unresolved.** This branch has them in
   the gateway (an `agents` table, `agent:<name>` cards in `/v1/models` —
   ADR 0062). The user has since said agents are "only within the chat". Both
   cannot be true; CLAUDE.md has the detail and the two questions still open
   with them. **Do not build on either side without asking.**

3. **`scripts/test_quota_race_live.py` cannot run in this configuration.** It
   wants Valkey on `localhost:6379`, which is deliberately unpublished (ground
   rule 4). Pre-existing, unrelated to today's work, and the only check of
   Redis `MULTI`/`EXEC` atomicity there is — so that property is currently
   unverified on this host.

## Deliberately unfinished

- **Web search is not reachable from the chat.** The backends, the metered
  `POST /v1/search` surface and the counting all exist; the chat never requests
  search and its own pipeline was deleted upstream in `2d549953`. This was the
  next task and was not started.
- **Agents cannot be published.** They reuse the sharing predicate, but only
  knowledge bases have publish/unpublish routes. Additive.
- **No UI for publishing anything** — neither console has a control for it.
- **The chat's custom-server code is retireable.** `AddServerForm.svelte` and
  the custom-server half of `mcpServers.ts` are superseded by connectors, and
  the localStorage migration already shipped, so this is now pure deletion. It
  was held back only to avoid colliding with another session.
- **Two identity shapes.** The local-login payload and `GET /v1/me` overlap but
  do not match; they should be one shape obtained two ways, or they will
  eventually disagree about groups.
- **Staan and Jina** are hooks, not backends. Staan's "for AI" tier is neither a
  documented request parameter nor reported back, and Jina publishes no
  per-token price at all — both need a real key before they can be implemented
  honestly.
- **No live script for `/v1/search`**, because we hold no vendor key.
- **The Playwright overlay lives in this repository and its only consumer is the
  chat.** The user has said it logically belongs with the chat and that the
  deployment layout should be reviewed; deferred deliberately.
